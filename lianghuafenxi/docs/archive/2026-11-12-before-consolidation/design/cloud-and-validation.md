# 免费云部署、安全与验收设计

v0.1，2026-11-11核对官方限制；未执行云部署。范围为个人使用、完整云端服务、无需付费订阅；免费配额及数据源权限仍受限制。

## 1. 云资源选择

| 资源 | 默认 | 说明 |
| --- | --- | --- |
| Workers Static Assets | 使用 | 同源提供React构建产物，私人原件不进入产物 |
| Workers Free | 使用 | 行情与资料网关，有界解析、校验、鉴权 |
| D1 Free | 可选 | 仅选持久模式时存私人资料 |
| Cache API | 使用 | 可丢弃的公开资料缓存，不是全局一致数据库 |
| KV / R2 / DO | 基础版不需要 | 避免无必要绑定与额外配额依赖 |
| Containers / Workers Paid | 排除 | 不符合当前无订阅路线 |
| Cron、后台采集、外部付费模型 | 排除 | 浏览器关闭停止跟踪 |

可使用workers.dev入口避免购买域名，发布前验证入口访问控制。默认生产与测试分开Worker；如用D1则分数据库。构建工具、Wrangler版本、compatibility_date锁定；配置示例是后续实施模板，不在本次创建真实云资源。

## 2. 配额预算与降级

核对依据：[Workers限制](https://developers.cloudflare.com/workers/platform/limits/)、[D1定价](https://developers.cloudflare.com/d1/platform/pricing/)、[D1限制](https://developers.cloudflare.com/d1/platform/limits/)。Workers Free每日100,000请求、每请求10ms CPU、128MB内存；D1 Free每日读500万行、写10万行，总5GB，单库500MB。D1调用与SQL绑定等还有独立上限，需在实现时核对。

预算以实际请求次数计算，不能把“刷新一轮”当成“一个请求”：

| 场景 | 5秒轮数 | 按每轮6请求估算 |
| --- | --- | --- |
| 连续4小时 | 2,880 | 17,280请求 |
| 连续8小时 | 5,760 | 34,560请求 |
| 连续24小时 | 17,280 | 103,680请求，超过日免费请求额度 |

6请求是假设323证券分5包、指数1包的预算样例；实际合并、市场状态和包大小会改变结果。另计资料、鉴权、重试、账户与导入请求。短缓存减少向供应商的取数，不必然减少进入Worker的请求；其他设备和应用也可能共用账户配额。

客户端预计预算接近阈值时提示并降频，服务端以可用平台数据报告实际消耗。不能用浏览器计数冒充整个Cloudflare账户的精确剩余额度。候选阈值：预计达到日预算70%提醒、85%降至15秒、95%报价60秒并暂停非必要取数，提供手动刷新。平台强制额度耗尽时API可能无法返回自定义错误，前端依据网络/HTTP错误显示云接口不可用，保留旧数据和本地导出。禁止自动升级付费。

历史全量323*约756交易日约24.4万根。按“一根一行”初始化已超过D1每日免费写行数，索引还可能增加计数。因此默认不把所有历史写D1：浏览器按需批量、会话内复用、详情优先。原始报价也不每5秒写库。财报短缓存、主数据低频刷新，写入次数须实测。

Worker CPU预算必须覆盖鉴权、JSON解析与标准化；网络等待与CPU不同。大响应解析、全量财报聚合、全账本回放放在浏览器或分块。有些Python公开源无法取得适合Worker的有界端点时，相关能力标记未通过，不强行声称免费方案全覆盖。

## 3. 访问控制及私有数据

推荐Cloudflare Access保护整个应用，只允许个人身份；Worker验证受信JWT签名、issuer、audience、有效期并由subject映射owner，未配置认证时私人API默认拒绝。部署前按[workers.dev文档](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)验证Access覆盖，检查预览地址、备用域名、静态路径及API无旁路。账户可用的免费Access设置和登录方式在部署时实际核验；若不可用，暂停公开私人API，先保留session方案，不发布裸露台账。

写请求校验Origin、JSON Content-Type和CSRF token；所有SQL参数化；请求体和数组有上限；日志脱敏，不记录数量/成本/备注/完整自选清单/访问令牌。响应私人资料 `Cache-Control: private,no-store`。公开缓存与私有响应分区，不能以缺owner的key缓存账户数据。

静态构建扫描排除历史持仓Markdown、截图、private目录、导入原件和密钥；secret不放VITE前缀变量，不输出到前端。CSV导出防公式注入；备注按纯文本渲染，来源HTML不能直接注入。导出文件会含私人资料，下载由用户主动操作。

完整自选清单向指定供应商发送的授权目前未补充，本设计不进行该测试。未来接入展示实际接收方、参数为证券代码以及用途，授权后仅发送必要参数；持仓数量、成本、备注不发送行情商。该约束来自之前完整清单取数被自动审批拒绝的已有状态，并非新增全站审批流程。

## 4. 运行状态、迁移与恢复

运行日志：request_id、路由模板、来源、耗时、CPU指标（平台可取时）、返回数、错误码。来源健康聚合不得反推私人股票清单。浏览器保留最近100条脱敏诊断，会话结束可丢弃。

版本号分别维护schema、适配器、公式、规则和构建版本。旧session导入先校验schema，支持明确迁移链，未知新版本拒绝覆盖现有数据。发布静态文件使用内容hash，接口至少兼容上一版前端，旧页面收到版本不兼容提示刷新，不破坏其未导出会话数据。

session恢复依赖主动JSON导出，不能承诺云端备份。D1模式可使用平台恢复能力并主动导出个人数据；[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)不替代长期备份。数据库迁移先在测试库验证，导出后再生产迁移；应用回滚不自动反向执行破坏性迁移。恢复演练核验账户数量、持仓、事件链、摘要、视图和提醒规则。

## 5. 数据源验证关卡

已有本机公开样本证明部分报价、历史、财报能返回，不能证明云端Worker能取、全清单字段完整、所有市场实时。尤其恒生/恒科样本约15分钟延迟、ETF全市场快照较慢、部分分钟开盘字段为0、汇率时点不足。

| 待验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| Cloudflare出口 | 公开A/H/ETF及九指数样本 | 真实Worker成功、字段可解析、时区单位正确 |
| 免费CPU | 报价包及历史/财报上限样本 | 平台CPU记录在Free限内，有余量；不是只看本机速度 |
| 行情新鲜度 | 各市场活跃交易段采样 | 展示源延迟分布，延迟源单列；5秒目标单独验收 |
| 323覆盖 | 获授权后按证券验证 | 每证券状态、字段、时间、币种与缺项清单，不只HTTP200 |
| 历史及复权 | A/H/ETF跨公司行为样本 | 三年窗口、因子基准、旧低点及日线正确 |
| 五年财务 | 不同行业和非自然财年样本 | 五年归母、收入、单位与披露日期正确 |
| 未证实能力 | 港股事件、控制权、最长历史等 | 取得可追溯来源，否则partial/unknown |

任何关卡失败应报告影响字段、替代来源可行性和成本；不将免费部署等同于免费实时行情授权。具体来源使用条件在适配器上线前核查。

## 6. 测试设计与阶段交付

测试使用公开/虚构样本，个人真实持仓仅用于用户可见的本地核对，不进入公开fixtures。

| 类别 | 必测案例 | 通过标准 |
| --- | --- | --- |
| 金额及事件 | 买入费用、卖出、清仓、分红、内部转移、未知费用、更正、同秒顺序 | 独立手算样例一致；不重复费用和现金流 |
| 并发/幂等 | 重复提交、异内容同键、两个标签同版本、回放中断 | 恰好一次生效；冲突显式；投影无半更新 |
| 存储 | session容量不足、刷新、关闭新开、JSON恢复；可选D1恢复 | 按模式声明行为，失败不假报保存成功 |
| 指标/规则 | 19.99/20、H=L、缺历史、负/零/缺利润、ETF、仓位约束 | 对应明确口径与带原因空值 |
| 实时 | 包超时、迟到报价、源切换、页面隐藏/关闭、断线重开 | 不倒退、不堆请求、空档不伪报穿越 |
| 页面 | 多筛选、阅读位置、统计下钻、备注、导入冲突、量额单位 | 截图与记录能逐项对应18项业务验收 |
| 安全 | 未登录、跨owner、CSRF、代理URL绕过、私有缓存、静态泄漏 | 请求拒绝，公开产物无私人资料 |
| 免费层 | 请求预算、CPU、SQL行读写、初载大量历史 | 有实测报告和降级；不启用付费资源 |

交付顺序：详细设计评审 → 六页面交互原型（虚构数据显著标识）→ 公共样本Worker可行性 → 会话领域服务和台账 → 行情图表及规则 → 18项业务验收 → 生产部署。若选D1，在台账阶段增加数据库迁移与一致性验收；当前不提前实施。

建议性能目标：有会话缓存首屏2秒内可操作；有效报价入浏览器后计算与渲染p95<1秒；初载323历史分批显示进度。取数耗时、源延迟、计算耗时分开报告。上述为验收目标，尚无本轮实测成绩。
